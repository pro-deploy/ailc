# ailc ROADMAP и честный статус зрелости

Этот файл честно фиксирует, что в ailc сделано и подтверждено, что сделано узко или
скелетом, и что ещё впереди. Источник истины это код и тесты; файл служит картой.

## Сделано и подтверждено (код и тесты)

- Детерминированный вердикт качества: гарантию даёт гейт, а не нейросеть. Минимум гейта
  по безопасности неотключаем, политика проекта сверяется с эталоном и помечает ослабление.
- Глубокий межпроцедурный анализ заражения (taint) доказан матрицей по пятнадцати языкам
  для трёх классов инъекций (исполнение команды, SQL, путь к файлу), с учётом санитайзеров.
- Статический разбор по абстрактному синтаксическому дереву (AST-SAST), правила OWASP и
  Web/API, каждое сообщение со ссылкой на CWE и OWASP.
- Чистка ложных срабатываний без потери реального сигнала: дедуп задвоенных правил,
  точность по контексту HTTP-клиента, правила доступности только по элементам разметки,
  исключение тест-кода и точек входа фреймворков, исключение защищённых XML-парсеров.
- Вывод SARIF 2.1.0 для непрерывной интеграции: в отчёт идут только подтверждённые находки,
  ложные опровергнуты, число опровергнутых и пропуски видны в свойствах.
- Definition of Done: многоосевой детерминированный вердикт «готово ли к сдаче».
- Правила сигналов соответствия требованиям РФ (152-ФЗ, 242-ФЗ, 187-ФЗ и ГОСТ) как сигналы
  для ревью.
- Лицензия Apache 2.0 на открытое ядро, оговорка о границах соответствия.
- Непрерывная интеграция: сборка release и тесты на каждый push и pull request.

## Полная генерация документов по стандартам (сделано)

- Извлечение фактов очищено от самозагрязнения: комментарии маскируются с сохранением
  строковых литералов, встроенные тесты гасятся, зависимости по окружению выводятся из
  извлечённых обращений, а не из упоминаний имени в тексте. До этого в спецификацию как
  эндпоинты продукта попадали примеры из таблиц правил самого анализатора, а как внешние
  зависимости строки из тестовых фикстур.
- Введена модель проекта (`.ailc/model/model.json`) с обязательным происхождением каждого
  факта: движок-источник, файл, строка, уверенность. Неустановленное ведётся честным
  перечнем пробелов с причиной. Схема модели защищена от расхождения тестом.
- Разделы стандартов объявлены данными, а не кодом: ГОСТ 19.201-78 (17 разделов),
  ГОСТ 34.602-2020 (37 разделов), arc42 версии 8 (24 раздела), модель C4 (8 диаграмм) с
  подлинной нумерацией и формулировками. Полнота документа по стандарту вычисляется
  детерминированно как доля закрытых обязательных разделов.
- Сведения, которых код не содержит, добываются опросом: `spec/questions` выдаёт очередь
  вопросов с черновиками из кода, `spec/answer` записывает ответ в реестр требований.
  Ключом ответа служит идентификатор раздела, поэтому ответ переиспользуется всеми
  документами комплекта и переносится при смене стандарта.
- Документ собирается целиком (`generate/doc`): титульные реквизиты, оглавление,
  нумерация по стандарту, лист регистрации изменений, отметка о полноте. Заглушек вида
  «заполни» не остаётся: незакрытый раздел несёт запись об отсутствии с указанием, чем её
  закрыть. Дописанный человеком абзац переживает регенерацию и помечается как возможно
  устаревший, если код с тех пор менялся.
- Полные уровни C4: контекст, контейнеры, компоненты, динамическая диаграмма и диаграмма
  развёртывания с обязательными элементами нотации (заголовок с областью охвата, легенда,
  тип элемента, технология, подписанные однонаправленные связи).
- Журнал изменений (`.ailc/changes/`) фиксирует любое, даже мелкое изменение; класс
  изменения выводится из различия, а не со слов агента. Расхождение документа с кодом
  стало блокирующим, прослеживаемость изменения блокирует соразмерно классу.
- Комплект документов объявлен декларациями для десяти документов: техническое задание по
  ГОСТ 19.201-78 и по ГОСТ 34.602-2020, пояснительная записка по ГОСТ 19.404-79, описание
  архитектуры по arc42, диаграммы по модели C4, описание автоматизируемых функций,
  описание информационного обеспечения, описание программного обеспечения, руководство
  пользователя, программа и методика испытаний. Перечень видов комплекта по
  ГОСТ Р 59795-2021 ведётся полностью, а неприменимые к программной системе виды
  документов сохраняются в перечне с обоснованием неприменимости, как предписывает сам
  стандарт.
- Прежние частичные генераторы спецификации, описания архитектуры и диаграмм C4 выведены
  из употребления в пользу выпуска документа целиком по декларации. Смена публичного
  состава возможностей записана архитектурным решением в журнале решений.
- Движки углублены. Метрики считают когнитивную сложность и глубину вложенности по дереву
  разбора, при этом прежняя цикломатическая величина сохранена без изменений, поскольку на
  неё настроены пороги политики и базовые линии долга. Движок запуска выдаёт паспорт
  инструмента с путём и версией (`verify/toolchain`), не выдумывая версию, если инструмент
  о ней умолчал. Место движка индексации занято детерминированным лексическим индексом с
  оценкой релевантности по классической формуле, без нейросети (`code.intel/search`).
- Извлечение объявлений даёт сигнатуру, комментарий документации автора и отношение
  наследования по дереву разбора, поэтому раздел о функциях частей программного
  обеспечения описывает, что каждая часть делает, а не только перечисляет имена. Описание
  не сочиняется: у объявления без комментария поле описания пусто, и это видно.
- Интерфейс командной строки (clap, argparse, click, cobra, commander, yargs, picocli) и
  конфигурационные параметры из файлов настроек извлекаются в модель. Из файлов настроек
  берутся только ИМЕНА параметров: значение сплошь и рядом содержит секрет, и его
  попадание в порождаемый документ было бы незаметной утечкой.

## Сделано после 0.6 (достоверность вердикта и стоимость поставки)

- Цепочка поставки: контрольная сумма обязательна во всех каналах установки, обёртка для
  npm сверяет её до распаковки, ограничивает перенаправления и устанавливает атомарно.
- Базовая линия долга не замораживает уязвимости важностью «высокая» и выше; отпечаток
  различает разные вхождения одного класса в одном файле.
- База уязвимостей собирается из официальных выгрузок OSV.dev (59 570 записей вместо 22)
  и обновляется еженедельно рабочим процессом с коммитом в репозиторий.
- Встроенная модель эмбеддингов удалена: подбор инструмента детерминирован, а при
  неуверенном отборе каталог отдаётся модели агента целиком. Бинарь 30,7 МБ вместо 72,1.
- Инкрементальность: повторный прогон при неизменном дереве занимает доли секунды.
- Профиль выпуска переведён на раскрутку стека, поэтому изоляция сбоев реально работает.
- Порядок обхода дерева детерминирован; подготовка проекта выполняется по явному вызову,
  а не при рукопожатии протокола.
- Метрики точности обнаружения выполняются в непрерывной интеграции и публикуются.
- Аварийных вызовов вне тестов не осталось: несобравшийся паттерн выключает своё
  правило, а не завершает процесс, и это закреплено тестами полноты.
- Артефакты выпуска подписываются без хранения ключей (cosign в режиме keyless), а
  установщики проверяют подпись, когда в системе есть cosign.
- Правило конституции компилируется из фразы естественного языка самим сервером,
  детерминированно и без сети.
- Архитектурные решения ведут жизненный цикл: статусы, двусторонние связи замены и
  проверка целостности журнала (`verify/adr-lifecycle`).
- Структурные пороги калибруются под размер и возраст репозитория в узком диапазоне;
  порог блокировки и веса балла не калибруются.
- Покрытие правил расширено тремя очередями (двадцать новых классов): заголовки
  безопасности, документные базы, подделка журнала, параметры выработки ключа, срок
  действия токена, перевод строки в заголовке, идентификатор сессии в адресе, ограничение
  частоты, трассировка стека в ответе, листинг каталога, зависимость по ветке, целочисленное
  переполнение, разыменование без проверки, гонка проверки и использования, а для нейросетей
  LLM06 и LLM08. Каждое правило снабжено парой тестов и вошло в контролируемый корпус.

## Сделано в 0.5 (автономность и онбординг)

- Паспорт проекта (`.ailc/profile.md`): детерминированное определение стека, интерфейса,
  мобильной части, признаков персональных данных, русскоязычности и обращений к нейросетям;
  от паспорта зависят умолчания проверок и жёсткость профильных осей вердикта
  (доступность UI, комплаенс РФ, безопасность ИИ).
- Серверное ведение памяти: журнал и активный контекст в `.ailc/memory-bank/` пишет сам
  сервер при каждом вызове инструмента; промпт «введи меня в курс дела» отдаётся средам.
- Базовая линия долга (`.ailc/baseline/`): первый контакт замораживает находки легаси,
  вердикт блокируют только новые; команда `ailc baseline`, метрика долга в DoD.
- Spec-first: классификация намерения (фича готовит спеку, ADR, бэклог и ветку до кода),
  мягкая ось прослеживаемости `spec.check/trace`, на сдаче автообновление документов и
  ретро-ADR по сигналу слома публичного контракта.
- Конституция: атрибуты правил `[warn]` и `[in: путь]`, обоснование после ` #`, раздел
  «Правила команды», добавление правила одной строкой (`governance/rule-add`) с немедленной
  примеркой к коду.
- Самообучение верификатора: хронически опровергаемые на проекте правила теряют голос до
  предупреждения с видимой пометкой (security-критичные исключены).
- Установка в одно действие: кнопки Cursor и VS Code, команда для Claude Code, `ailc doctor`.

## Впереди (дорожная карта открытого ядра)

- Подпись и нотаризация сборок платформенными средствами (Apple Developer ID для macOS,
  Authenticode для Windows). Без них операционная система показывает предупреждение при
  первом запуске. Требует платных учётных записей разработчика и хранения сертификатов,
  поэтому выполняется владельцем продукта, а не автоматикой. Подпись артефактов выпуска
  уже действует: она сделана без ключей (cosign keyless) и проверяется установщиками.
- Английская локализация технического слоя. Сейчас на русском языке не только документация,
  но и тексты находок, что сужает применимость продукта за пределами русскоязычных команд.
- Расширение покрытия языков и правил. Сделаны четыре очереди (сорок девять классов), см.
  CHANGELOG; далее по мере запросов от пользователей.

## Коммерческие дополнения (по отдельной лицензии, вне открытого ядра)

Открытое ядро находит и показывает сигналы. Платные дополнения распространяются отдельно
по коммерческой лицензии и в этот репозиторий не входят: аттестационный отчёт по комплаенсу
(превращает сигналы в документ для аудитора со статусами требований и доказательствами),
уровень команды (центральная панель, сведение находок по многим репозиториям, блокировка
запросов на слияние в конвейере) и уровень предприятия (локальный управляющий слой,
разграничение доступа, журнал аудита, поддерживаемые пакеты соответствия как подписка).

## Известные ограничения

- Анализ заражения теряет поток через поля объектов и коллекции; санитайзеры из курируемого
  списка контекст-независимы. Ветвления обрабатываются с объединением состояний, а охранная
  проверка по разрешающему списку или на равенство константе признаётся санитайзером, однако
  произвольная валидация (регулярное выражение, вызов проверяющей функции) им не считается.
- Часть правил Web построчны; модель памяти C и C++ упрощена.
- Встроенный снимок базы уязвимостей не содержит записей о вредоносных пакетах (`MAL-*`):
  их сотни тысяч, и они раздули бы поставку на порядки. Для этого класса угроз запускайте
  штатный аудитор экосистемы.
- Сервер протокола MCP держит запущенный процесс, поэтому после обновления бинаря его
  необходимо перезапустить: до перезапуска он отвечает прежней версией.
- Само-срабатывания при сканировании собственных исходников возможны, как у любого сканера:
  таблицы правил и фикстуры содержат образцы уязвимого кода. Тестовые модули и комментарии
  из источников исключены, но отдельные следы (например имя переменной окружения из самого
  паттерна детектора) остаются.
