# Этап 3. ADR

**Роль:** модель с ailc, команда проверяет

## Цель
Зафиксировать ключевые решения с альтернативами и причинами выбора.

## Входы
docs/brief.md, docs/landscape.md, существующие ADR в .ailc/decisions/.

## Шаги для модели
1. Прочитай действующие ADR, чтобы не противоречить им. Если новое решение отменяет старое, пиши в заголовке «заменяет ADR-N».
2. Для каждого решения вызови run с id generate/adr и query = название решения. Запись создаётся по шаблону .ailc/templates/adr.md.
3. Заполни все обязательные разделы, вариантов не меньше двух.
4. Для новой фичи вызови design, чтобы получить заготовку спецификации.

## Инструменты ailc
generate/adr, verify/adr-lifecycle, design, memory/decision-log.

## Запрещено на этом этапе
Писать код, ставить ADR статус «принято» (это делает человек на этапе 5).

## Обязательный результат
Хотя бы один ADR со статусом «предложено» и заполненными обязательными разделами.

## Условие перехода
Есть хотя бы один ADR, verify/adr-lifecycle без находок. Затем stage advance.

## Сделай сейчас
Перечисли решения, которые нужно принять по брифу и карте ландшафта, и создай первый ADR.
