# Этап 4. Критерии приёмки и метрики

**Роль:** модель с ailc, команда проверяет

## Цель
Превратить ожидания заказчика в измеримые критерии с порогом и способом замера.

## Входы
docs/brief.md (цель и метрика), ADR, .ailc/templates/acceptance.toml.

## Шаги для модели
1. Скопируй .ailc/templates/acceptance.toml в .ailc/process/acceptance.toml, если файла нет.
2. Для каждого пункта объёма и для цели из брифа добавь блок [[criterion]] с порогом, оператором, единицей и командой замера.
3. Для доработки существующей системы обязательно добавь критерии вида regression: тесты зелёные, нет ломающих изменений API, производительность не хуже текущей.
4. Вызови stage с action=status: он покажет строки без порога или без команды.

## Инструменты ailc
stage (проверка критериев), verify/api-break, generate/api-baseline.

## Запрещено на этом этапе
Писать код, использовать слова без чисел («быстро», «удобно»).

## Обязательный результат
.ailc/process/acceptance.toml, где у каждой строки есть threshold, op, unit и command.

## Условие перехода
Все критерии валидны. Затем stage advance.

## Сделай сейчас
Открой .ailc/process/acceptance.toml и добавь критерий для метрики успеха из брифа.
