# Участие в развитии ailc

Спасибо за интерес к проекту. Ниже изложен порядок, которого мы придерживаемся.

## Прежде чем писать код

Обсудите замысел в задаче (issue). Для исправления очевидной ошибки обсуждение не
требуется, для нового правила, нового инструмента или изменения поведения вердикта
требуется: состав проверок и жёсткость осей влияют на всех пользователей продукта.

Открытые направления работ перечислены в файле [ЗАДАЧИ.md](ЗАДАЧИ.md) с оценкой
серьёзности и доказательствами, а карта зрелости в файле [ROADMAP.md](ROADMAP.md).

## Требования к изменению

Сборка выполняется зафиксированной версией инструментария из `rust-toolchain.toml`.
Перед отправкой запроса на слияние изменение обязано проходить те же проверки, что и
непрерывная интеграция:

```bash
cargo fmt --all -- --check
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace
cargo build --release -p ailc && ./target/release/ailc dod .
```

Каждое изменение поведения сопровождается тестом. Для нового правила обнаружения
требуются два теста: на срабатывание (истинно положительный случай) и на молчание
(контроль ложного срабатывания на близком, но безопасном коде). Правило без второго
теста не принимается: точность для этого продукта важнее полноты.

Изменение, затрагивающее состав возможностей или числовые характеристики продукта,
обновляет README вместе с кодом. Расхождение закреплено тестом `readme_matches_registry`
и приведёт к падению сборки.

Изменения, заметные пользователю, вносятся в раздел «Не выпущено» файла
[CHANGELOG.md](CHANGELOG.md).

## Стиль

Комментарии и документация пишутся по-русски, полными предложениями, с объяснением
причины решения, а не пересказом кода. Комментарий отвечает на вопрос «почему так»,
поскольку «что делает» видно из самого кода.

Сообщения коммитов оформляются по образцу `тип(область): краткое описание`, где тип это
`feat`, `fix`, `docs`, `refactor`, `test`, `ci` или `chore`.

## Лицензия и права

Проект распространяется по лицензии Apache 2.0. Отправляя изменение, вы соглашаетесь на
его распространение по этой лицензии и подтверждаете, что вправе его передать.

Отдельного соглашения участника (CLA) пока нет. Если оно будет введено в связи с
коммерческими дополнениями, распространяемыми по отдельной лицензии, действующие
участники будут уведомлены заранее.

## Сообщения об уязвимостях

Уязвимости не обсуждаются в публичных задачах. Порядок изложен в файле
[SECURITY.md](SECURITY.md).
