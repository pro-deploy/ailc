# security.scan/ci

Опасные конструкции рабочих процессов непрерывной интеграции в файлах YAML: подстановка недоверенного поля события (заголовок задачи, заголовок и ветвь запроса на слияние, текст комментария) внутрь исполняемой команды, событие pull_request_target вместе с получением кода из ветви запроса, права токена write-all, использование действия по подвижной ссылке вместо закрепления по отпечатку коммита, печать секрета в журнал, собственный исполнитель для проверок постороннего вклада. Правила рассчитаны прежде всего на рабочие процессы GitHub Actions; для сценариев GitLab CI применимо правило о печати секрета.

## Как запустить

Через MCP-сервер ailc (один офлайновый бинарь, без внешних сервисов):

- `run { "id": "security.scan/ci", "path": "<путь к проекту>" }`
- семантический подбор под намерение: `find_capability { "query": "..." }`

Через CLI:

```
ailc cap security.scan/ci <путь>
```

Находки возвращаются структурно (file:line + severity) и проходят состязательную верификацию — в балл и гейт идут только подтверждённые. Семейство `security`, движок `scan`, тир `core`.
